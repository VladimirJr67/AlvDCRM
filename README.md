# Алвид CRM

Локальная CRM для работы с клиентами, задачами и заказами: один сервер на весь
офис, база — файл `db.json` рядом с сервером. Без сборки и внешних зависимостей.

## Быстрый запуск

1. Двойной клик по **`start.bat`** (либо в терминале: `node server.js`).
2. Браузер откроется сам: **http://localhost:3000**
3. Вход по умолчанию: `Admin` / `Admin` — администратор, `manager` / `manager` — менеджер.
   Форма входа всегда пустая: поля не подставляются ни браузером, ни приложением.

Окно сервера закрывать нельзя, пока работаете в CRM. Остановить — `Ctrl+C`.

> `npm start` в PowerShell не сработает: политика выполнения скриптов блокирует
> `npm.ps1`. Используйте `start.bat` или `cmd /c npm start`.

## Роли и вход

Роли в системе три: **администратор** (`admin`), **менеджер по продажам**
(`manager`), **руководитель** (`lead`). Роли «technolog» нет и не планируется:
у технологов отдельный контур работы. Историческое значение роли `user`
(так раньше обозначался менеджер) при миграции приводится к `manager`.

Вход сохраняется между перезагрузками страницы и перезапуском сервера:

- при входе сервер выдаёт две **httpOnly** cookie — `alvid_sid` (access, 30 минут)
  и `alvid_refresh` (refresh, 90 дней). Скрипты страницы их не читают;
- когда access истёк (вкладка была открыта давно, страницу перезагрузили после
  паузы), сервер молча выдаёт новый по refresh-токену — пользователя **не
  разлогинивает**;
- пока окно открыто, приложение раз в 20 минут продлевает сессию
  (`POST /api/auth/refresh`), поэтому активный вход не истекает;
- выход — только кнопкой **«Выйти»**: она гасит и серверную, и локальную сессию.

Активные входы лежат в служебном файле `sessions.json` — только хеши
refresh-токенов, сам токен там не хранится. Файл в git не попадает.

## Схема базы и миграция

Схема `db.json` — версия **6**. При старте сервер сам проверяет базу и
дописывает недостающие поля, ничего не удаляя; перед записью рядом
сохраняется копия вида `db.json.v5.<дата>.bak` (откат — вернуть её на место
`db.json`). Отдельный шаг миграции без запуска сервера:

```
node server.js --migrate
```

Что объявлено в схеме:

| Поле | Назначение |
|---|---|
| `clients.oldBaseId`, `clients.responsibleManagerId` | id карточки в прежней базе и ответственный менеджер |
| `clients[].history[]` (комментарии) | `tags: ['forSelf'/'forReport']`, `closedAt`, `nextActivityAt`, `activityType`, `columnId`, `taskId` |
| `contacts[].comments[]` | те же поля комментария у контактных лиц |
| `specialNotes[]` | особые отметки — отдельно от комментариев |
| `taskColumns[]` + `taskColumnsPerManager` | глобальные столбцы канбана и индивидуальные наборы по менеджерам |
| `activityToColumnMap` | привязка типа активности к столбцу канбана |
| `matrices[]` | заказы матриц: шифр, покрытие, статус «Поступила»/«Отписана», клиент, дата |
| `clientTransferRequests[]` | запросы на перенос клиента к другому менеджеру |
| `chatManagers[]`, `chatLeads[]` | чаты менеджеров и руководителей |
| `notifications[].position`, `notifications[].sound` | где показать уведомление и со звуком |
| `users.theme`, `users.substituteFor`, `users.substituteUntil` | тема оформления и замещение |
| `tasks.trackingBy[]`, `tasks.linkWorkedOff`, `tasks.colleagueId` | кто следит за задачей, отработана ли ссылка, коллега |
| `tasks.kind`, `tasks.linkUrl` | вид задачи (`regular` / `link` — «Отработка ссылки») и ссылка |
| `users.trackedBy[]` | руководители, отслеживающие задачи сотрудника |

Интерфейс оформлен без эмодзи: пиктограммы заменены текстовыми подписями
(«Изменить», «Удалить», «обязательный»), заголовки разделов — просто текстом.

Индивидуальные столбцы лежат в отдельном ключе `taskColumnsPerManager`
(`{ '<id пользователя>': [ столбец ] }`): массив `taskColumns` не может нести
собственное свойство `perManager` — JSON его теряет.

## Активности и задачи

Любой комментарий в карточке клиента (и «Особая отметка») — это активность
с типом из справочника. У неё два следствия: правило закрытия и задача.

**Правило закрытия.** Активность закрывается только вместе со следующей датой
активности — поле «Следующая активность» обязательно. Единственное исключение —
тип **«Нерентабелен»**: он закрывает активность без следующего шага. Записи без
даты остаются «не закрытыми» и так и помечены в карточке — их можно дозакрыть,
задав дату при правке.

**Задача.** После подтверждения комментария задача автоматически встаёт в тот
столбец доски, который администратор привязал к этому типу активности
(Администрирование → **Столбцы задач**). Дата следующей активности становится
сроком задачи. Если тип ни к чему не привязан, задачи нет — остаётся только
комментарий (так работает «Информация»).

Рекомендуемые привязки из ТЗ (кнопка **«Создать столбцы и привязки по ТЗ»**
создаёт недостающие столбцы и связывает их одним нажатием — сама система
столбцы не заводит):

| Активность | Столбец задачи | Что ещё происходит |
|---|---|---|
| Звонок | Звонки | — |
| Отправил КП | Отправлено КП | — |
| Встреча | Встреча | выбор коллеги: ему создаётся такая же задача и уходит уведомление |
| Размещение заказа | Заказы | запись в «Заказах» (старая система), комментарий остаётся в комментариях |
| Заказ матриц | Заказы/Матрицы | окно шифров и покрытия: на каждый шифр — запись в `matrices[]` со статусом «Поступила», комментарий помечается «Для отчёта» |
| Информация | — (не привязывать) | только комментарий |

Матрицы видны в разделе **«Заказы/Матрицы»** на вкладке «Матрицы».

## Раздел «Заказы/Матрицы»

Раздел состоит из двух независимых вкладок:

**Заказы** (старая система). Запись создаётся комментарием с типом «Размещение
заказа». Менеджер видит только свои заказы, администратор — все или заказы
выбранного пользователя; у нового аккаунта вкладка пуста. Фильтры: по клиенту,
по покрытию и по периоду («Анализ продаж» — выбрать период или «Сегодня»).
Экспорт в Excel доступен только администратору. Метрики «средний чек» в системе
нет — считаются только количество, вес и сумма.

**Матрицы**. Поля записи: шифр, клиент, покрытие (**Сырой / Анод / Покраска**),
статус (**Поступила / Отписана**) и дата. Записи появляются из активности «Заказ
матриц» (по одной на каждый шифр) или вручную кнопкой «+ Добавить матрицу»;
статус переключается прямо в таблице. Права и пустое состояние у нового аккаунта
такие же, как у заказов. Фильтры вкладки свои, отдельно от фильтров заказов: по
клиенту, по покрытию, по статусу, по периоду; администратору доступен ещё
фильтр по пользователю. Экспорт в Excel — только администратор.

## Минимальные цены за КГ

Блок стоит в боковом меню **над «Курсами»**. Три цены — **Анод, Сырой,
Покраска**; у каждой видна дата последнего изменения, а полная история правок
открывается кнопкой «История изменения цен» (кто, когда, было/стало).

Меняет цены только администратор: клик по блоку открывает форму с тремя
полями, пустое поле убирает цену. Значения общие для всех и сохраняются в
`minPrices`, история — в `minPriceHistory`.

В записи комментария активность хранится в полях `closedAt`, `nextActivityAt`,
`activityType`, `columnId` и `taskId` (номер созданной задачи).


## Как подключить коллег

Коллегам нужен адрес этого компьютера в локальной сети — например
`http://192.168.0.165:3000` (свой IP смотрится командой `ipconfig`).
Изменения сразу видны всем: данные лежат в общей базе `db.json`.

## Настройки, которые стоит сделать сразу

- **Должности пользователей** — Администрирование → Пользователи. Без них выбор
  соисполнителя покажет только ФИО.
- **Ключ Дадаты** — Администрирование → Интеграции: включает автозаполнение
  реквизитов по ИНН и точные подсказки городов. Ключ хранится на сервере в
  `config.local.json` и в git не попадает.
- **Справочники** типов организаций и должностей наполняются сами — из уже
  введённых карточек и из импортов, и сразу доступны всем менеджерам.

## Импорт клиентов

Раздел «Клиенты» → кнопки **«Шаблон»** (скачать файл с колонками и примером) и
**«Импорт»**. Колонки ищутся по названию с синонимами, поэтому порядок столбцов
в файле не важен. Поддерживаются `.xlsx`, `.xls` и `.csv`.

## Резервная копия

Вся база — один файл `db.json` в папке проекта: для бэкапа достаточно его
скопировать. Чтобы начать с чистой базы, остановите сервер, удалите `db.json` и
запустите снова — файл создастся заново с пользователями по умолчанию.

## Важно про безопасность

Вход теперь серверный (httpOnly cookie), но **проверка сессии на остальных API
пока не включена**: любой, кто знает адрес, по-прежнему видит и может изменить
всю базу через `/api/db`, включая пароли пользователей — они хранятся открытым
текстом. Используйте CRM только в доверенной локальной сети и не выставляйте
порт 3000 в интернет. Включать обязательную сессию для `/api/*` нужно отдельным
шагом — тогда доступ к базе без входа закроется.

## Чат, переносы клиентов и профиль

**Чат менеджеров** — изолированный раздел: его видит и может писать только
сотрудник с ролью «менеджер по продажам» (`manager`). Администратор и
руководитель пункта меню не получают, а прямой вызов отправки им отказывает.
Сообщения лежат в общей коллекции `chatManagers`, непрочитанные считаются по
списку `readBy` и показываются счётчиком на пункте меню; остальные менеджеры
получают уведомление о новом сообщении.

**Переносы клиентов** — клиент переходит к другому менеджеру только через
запрос: менеджер отправляет его из карточки клиента (кнопка «Отправить запрос на
перенос»), а решение принимает тот, кому клиента передают, — **«Принять»** или
**«Отклонить»** в разделе «Переносы клиентов». Пока решения нет, клиент остаётся
за прежним менеджером; автор может отменить свой запрос. Администратор, как и
раньше, может передать клиента сразу (кнопка «Передать сразу»). Запросы лежат в
`clientTransferRequests`, у получателя на пункте меню — счётчик входящих.

**Профиль** открывается кнопкой рядом с «Выйти» и хранит ФИО, телефон, отдел,
должность и фото (сжимается до 200×200 в data-URL). Там же — тема оформления,
звук и позиция уведомлений и разрешение на системные попапы.

## Тёмная тема

Переключается в профиле (поле «Тема оформления»), применяется сразу и хранится в
`users.theme` — то есть у каждого своя. Реализована слоем переопределений поверх
светлых стилей: цвета собраны в переменные, правила включаются классом
`theme-dark` на `<body>` (его ставит `applyTheme()` из `js/profile.js`).

Часть разметки разделов собирается с inline-цветами (`style="background:#fff"`),
поэтому в конце `css/style.css` есть блок правил по подстроке `style="…"` — он
временный: когда разделы перейдут на классы, его можно убрать. Проверка покрытия
(доля почти белых пикселей на отрисованной странице): светлая тема 93 %, тёмная
3 % — то есть белых блоков в тёмной теме не остаётся.

## Системные уведомления поверх всех окон

Уведомления показываются системой через Web Notifications API, поэтому видны
поверх любых окон, даже когда CRM свёрнута. Показ идёт через Service Worker
`sw.js` (`registration.showNotification`), клик по попапу поднимает окно CRM; если
Service Worker недоступен — через `new Notification()`, а если и его нет — остаётся
всплывающая карточка внутри страницы.

Разрешение запрашивается в профиле кнопкой «Включить системные уведомления»;
там же можно выключить попапы, выбрать звук (5 базовых, синтезируются Web Audio)
и позицию (четыре угла и центр). Свой попап и звук показывает только адресату:
`notifyUser` сравнивает `userId` с текущим пользователем, поэтому коллега увидит
уведомление у себя, а не у вас.

> Системные попапы требуют защищённого контекста: `http://localhost` подходит, а
> адрес по локальной сети (`http://192.168.0.165:3000`) — нет, браузер такие
> уведомления там запрещает. В этом режиме остаются попапы внутри страницы.

Раздел можно открыть ссылкой: `http://localhost:3000/?section=chat` (список
разделов — в `STARTABLE_SECTIONS` в `js/app.js`).

## Доска задач

**Столбцы.** Управляет столбцами только администратор — в разделе
**«Администрирование → Столбцы задач»**:
глобальные столбцы появляются у всех менеджеров, индивидуальные — только на
доске выбранного менеджера (хранятся в `taskColumnsPerManager`). Столбец можно
переименовать, перекрасить, сдвинуть влево-вправо и удалить; удалённый исчезает
с доски, а его задачи переезжают в первый оставшийся столбец. Обязательные
столбцы (бизнес-статусы дашборда) защищены от переименования и удаления.
На самой доске кнопок правки нет: там столбцы только показываются — так доска
выглядит одинаково у всех.

Там же настраивается **привязка активностей к столбцам**, включая вариант
«не привязывать» (активность останется только комментарием, как «Информация»).
Если привязанный столбец удалили, привязка снимается автоматически, а в разделе
появляется подсказка выбрать новый.

**Назначение задач.** Пункта «Задачи» в администрировании нет: назначать задачи
сотрудникам (и снимать назначение) можно прямо из главного меню **«Задачи»** —
в карточке задачи поле «Назначить исполнителю». Оно доступно администратору и
руководителю; исполнитель получает уведомление и видит задачу в своём столбце
«Назначенные задачи», где сам меняет статус назначения.

**Календарь пластами.** Над доской — лента периодов с переключателем
День / Неделя / Месяц: в каждом пласте показано количество задач этого срока
(день — по часам, неделя — семь дней, месяц — дни месяца). Стрелки ‹ › листают
периоды, «Сегодня» возвращает текущий. Клик по пласту оставляет на доске только
задачи этого срока, повторный клик или «Показать все задачи» снимает фильтр;
пласты с просроченными задачами подсвечены красным. Счётчики считаются по полю
`tasks.deadline`.

**Отслеживание задач (руководитель).** Раздел доступен руководителю и
администратору: он выбирает сотрудника и видит прогресс — сколько задач всего,
в работе, просрочено, процент выполнения и разбивку по столбцам. Отслеживаемый
сотрудник становится наблюдателем (`tasks.trackingBy`) своих текущих задач, а
его новые задачи получают наблюдателя автоматически (`users.trackedBy`).

**Задача-ссылка.** В карточке задачи есть вид «Отработка ссылки» и поле ссылки.
Такую задачу нельзя перевести в завершающий столбец — ни перетаскиванием, ни
сохранением формы, — пока на карточке не отмечена галочка «Ссылка отработана»
(`tasks.linkWorkedOff`, отметка времени — в `linkWorkedOffAt`).

**Стрелки рабочей зоны.** Прокрутка доски считается в `requestAnimationFrame`:
короткий клик — плавный сдвиг на ширину колонки с замедлением в конце,
удержание — непрерывное движение с разгоном. Стрелки стоят по центру рабочей
зоны (с поправкой на полосу горизонтальной прокрутки).

**Попап напоминания** только показывает напоминание: кнопка «Закрыть» убирает
его с экрана, а отметка «выполнено» делается в разделе «Напоминания».

node __test_chat_transfers_theme.js # чат, переносы через запрос, тема, попапы

node __test_admin_columns.js        # раздел столбцов, назначение из «Задач», привязки
node __test_handlers.js             # все inline-обработчики существуют

`__test_auth.js` работает в две фазы: `phase1` — вход и проверки cookie,
`phase2` — после перезапуска сервера сессия жива, затем выход.
`__test_activities.js` выполняет настоящие функции приложения в песочнице с
заглушкой DOM: проверяет правило следующей даты, попадание активности в нужный
столбец, задачу коллеге по встрече и записи матриц.
`__test_orders_matrices.js` так же проверяет вкладки раздела, права доступа,
фильтры и сохранение минимальных цен.
`__test_admin_columns.js` — что раздела «Задачи» в администрировании нет,
назначение работает из главного меню «Задачи», а столбцы и привязки активностей
настраиваются администратором.
